## 1. 问题：下一步该做什么

模型效果不好，摆在面前的选项：

- 收集更多训练数据
- 减少特征
- 增加特征
- 加多项式特征
- 减小 λ
- 增大 λ

每一条都要花几周。**随便挑一条试，有一半概率是纯浪费时间。** 诊断的意义就是提前知道该挑哪条。

## 2. 数据划分：train / cv / test

```
60% train  |  20% cross-validation  |  20% test
```

（数据很大时，cv/test 各 1% 就够了——1% 的 100 万还是 1 万。）

**为什么是三份而不是两份**：

只要你用某个集合去**做选择**（选多项式次数、选 λ、选架构、选阈值），这个集合上的误差就变成了乐观估计——你选的正是在它上面碰巧最好看的那个。所以：

- **cv 集**承担所有选择
- **test 集只在最后碰一次**，用来报告一个诚实的泛化估计

> 这是全课程最容易被违反的一条纪律。如果你用 test 集调过任何东西，你报告的 test 误差就已经不诚实了。

cv 集别名很多：validation set / development set / dev set，指同一个东西。

```python
from mlkit.diagnostics import train_cv_test_split
X_tr, y_tr, X_cv, y_cv, X_te, y_te = train_cv_test_split(X, y, 0.6, 0.2, seed=0)
```

## 3. 误差怎么算

- 回归：`J = (1/2m) Σ (f−y)²`（正则项**不计入**评估用的 J，λ 只在训练时起作用）
- 分类：用**误分类比例**（`1 − accuracy`）比用逻辑损失更直观

## 4. ★ 偏差与方差诊断

```
J_train 高，J_cv ≈ J_train        →  高偏差（欠拟合）
J_train 低，J_cv ≫ J_train        →  高方差（过拟合）
J_train 高，且 J_cv ≫ J_train     →  两者都有（少见）
J_train 低，J_cv 低                →  没问题
```

### 与基准水平（baseline）比才有意义

语音识别里 J_train = 10.8% 听起来很糟，但如果**人类**在同样嘈杂的音频上也有 10.6% 的错误率，那这个模型几乎没有可改进的偏差——数据本身就这么难。

```
baseline ──(可避免偏差)── J_train ──(方差)── J_cv
```

- baseline → J_train 的差 = **可避免偏差 (avoidable bias)**
- J_train → J_cv 的差 = **方差**

**哪一段大就修哪一段。** baseline 可以取人类水平、竞品表现，或先验经验。

```python
from mlkit.diagnostics import bias_variance_report
print(bias_variance_report(j_train=0.108, j_cv=0.145, baseline=0.106))
# avoidable bias 0.002, variance gap 0.037 -> high variance
```

### 正则化 λ 与偏差方差的关系

| λ | J_train | J_cv | 状态 |
|---|---|---|---|
| 0 | 很低 | 很高 | 高方差 |
| 适中 | 低 | 低 | ★ |
| 很大 | 很高 | 很高 | 高偏差 |

**J_train 随 λ 单调上升**（约束越强，训练集拟合越差）；**J_cv 是 U 形**。取 J_cv 的谷底。

注意这条 J_train 曲线的走向和"多项式次数"那张图正好相反（次数越高 J_train 越低）——两张图别记混。

## 5. 学习曲线（J vs 训练集大小 m）

普遍规律：**m 越大，J_train 越高，J_cv 越低**，两条线相向而行。
- J_train 上升：样本少时容易全部拟合完美，样本多了就顾不过来
- J_cv 下降：见得多学得好

### 两种病的形态

**高偏差**：两条线很快就**拉平并靠拢**，且停在一个很高的水平上。

```
J
│ ────────────── J_cv
│ ────────────── J_train      两条几乎重合，都远高于 baseline
│ ······· baseline
└──────────────────► m
```
→ **加数据没用**。曲线已经平了，再多数据也压不下去。这是最重要的一条结论，能省掉几个月的数据收集。

**高方差**：J_train 很低（甚至低于 baseline，因为在过拟合），J_cv 高，**中间有很宽的缝**，且缝随 m 增大慢慢收窄。

→ **加数据有用**。

```python
from mlkit.diagnostics import learning_curve
sizes, jt, jc = learning_curve(fit_predict, X_tr, y_tr, X_cv, y_cv, error_fn)
```

## 6. 对症下药表

| 症状 | 该做什么 | 不该做什么 |
|---|---|---|
| **高方差** | 收集更多数据 / 减少特征 / **增大 λ** | 换更大的模型（更糟） |
| **高偏差** | 增加特征 / 加多项式特征 / **减小 λ** / 换更大的网络 | 收集更多数据（白费） |

## 7. 神经网络与偏差方差

大型神经网络在中小数据集上**几乎总是低偏差机器**。所以有一个很实用的循环：

```
① J_train 够好了吗？
   否 → 用更大的网络（更多层/更多单元），回到 ①
   是 → ②
② J_cv 够好了吗？
   否 → 收集更多数据，回到 ①
   是 → 完成
```

关键事实：**只要正则化得当，更大的网络几乎不会比小网络更差**（代价只是算得慢）。所以"网络太大会过拟合"这个担心在有正则化时基本不成立。

Keras 正则化写法：`Dense(units=25, activation='relu', kernel_regularizer=L2(0.01))`
本仓库：`NeuralNetwork([...], [...], lambda_=0.01)`

## 8. 机器学习开发的迭代循环

```
选架构（模型/数据/超参） → 训练 → 诊断（偏差方差 + 误差分析） → 回到第一步
```

### 误差分析（和偏差方差诊断同等重要）

拿 cv 集里**分错的样本**，手工看 100 个（多了就随机抽 100 个，人能处理的量），按原因归类，统计每类多少个。

垃圾邮件例子：500 个分错的，抽 100 个来看
- 卖药广告：21 个
- 故意拼错单词（w4tches）：3 个
- 钓鱼邮件：18 个
- 异常的邮件头：5 个

结论：花几个月做"防拼写变形"的特征，最多改善 3 个样本；而卖药和钓鱼加起来 39 个，才是该攻的方向。

**误差分析的局限**：只对人类能判断对错的任务有效。预测点击率这种人也说不清的任务就用不上。

## 9. 增加数据的三种方式

1. **只加你缺的那类**：误差分析说钓鱼邮件是大头，就专门去多搞钓鱼邮件样本，比无差别加数据高效得多。
2. **数据增强 (data augmentation)**：对已有样本做变换生成新样本。
   - 图像：旋转、缩放、改对比度、镜像、加网格扭曲
   - 音频：叠加人群噪声、车内噪声、模拟差信号
   - ★ **原则：加的失真必须是测试集里真实会出现的**。给图片加纯随机像素噪声通常没用，因为真实照片不长那样。
3. **数据合成 (data synthesis)**：从零造。比如用电脑字体渲染各种文字图片来训练 OCR。

### 数据中心 vs 模型中心

过去几十年是"model-centric"：数据固定，改进算法。现在算法（线性回归/神经网络/树）已经足够好，往往**"data-centric"——固定算法，改进数据**回报更高。

## 10. 迁移学习（数据很少时的救命稻草）

两步：
1. **监督预训练**：在一个大数据集（如 100 万张普通图片，1000 类）上训练一个网络
2. **微调 fine-tuning**：把输出层换成你自己的（比如 10 类手写数字），然后
   - 选项 A：只训练输出层参数（数据极少时）
   - 选项 B：所有参数都继续训练（数据稍多时）

**为什么有效**：前几层学到的是通用视觉特征——边缘 → 角点和曲线 → 基本形状。这些对任何图像任务都有用，不需要重学。

**限制**：输入类型必须一致。图像预训练模型不能用到音频任务上。

这也是"下载别人预训练的模型"这件事的理论依据（GPT、BERT、ImageNet 模型都是这个思路）。

## 12. 倾斜数据集

正例只占 0.5% 时，"永远预测 0" 就有 99.5% 准确率，但毫无用处。**准确率在这种数据上是无效指标。**

```
              预测1    预测0
实际1          TP       FN
实际0          FP       TN

Precision 精确率 = TP/(TP+FP)   报警的里面有多少是真的
Recall    召回率 = TP/(TP+FN)   真的里面有多少被抓到了
```

**权衡**：
- 提高阈值（比如 0.7 才判 1）→ 更保守 → **精确率↑，召回率↓**（适合误报代价高，比如误诊导致有创治疗）
- 降低阈值（0.3 就判 1）→ 更激进 → **精确率↓，召回率↑**（适合漏报代价高，比如癌症筛查）

阈值**不能靠 J 自动选**，要根据业务代价手动定。

**F1 分数** = `2PR/(P+R)`（调和平均），用来在多个模型之间比较时给出单一数字。

用调和平均而非算术平均：P=1.0, R=0.0 的算术平均是 0.5（看着还行），调和平均是 0。**F1 拒绝奖励放弃了其中一边的模型。**

```python
from mlkit.diagnostics import threshold_sweep
thr, p, r, f1 = threshold_sweep(y_cv, model.predict_proba(X_cv))
best_thr = thr[f1.argmax()]        # 在 cv 集上选阈值，不是 test 集
```

## 13. 做项目时的检查清单

1. [ ] 先切好 train/cv/test，把 test 集**锁起来**
2. [ ] 定好评估指标（倾斜数据用 F1，不用准确率）
3. [ ] 估一个 baseline（人类水平 / 简单规则）
4. [ ] 跑一个最简单的模型拿到 J_train / J_cv
5. [ ] 做偏差方差诊断，决定方向
6. [ ] 做误差分析，决定优先级
7. [ ] 迭代，每次只改一件事，重新看诊断
8. [ ] 最后碰一次 test 集，报告数字
