# 第一部分：K-means

## 1. 无监督学习的转变

监督学习给的是 (x, y)，无监督学习**只有 x**。没有"正确答案"可以对比，算法要自己在数据里找结构。

## 2. 算法

随机初始化 K 个簇中心 μ₁…μ_K，然后重复：

**步骤 1（分配）**：把每个点分给最近的中心
```
c⁽ⁱ⁾ = argmin_k ‖x⁽ⁱ⁾ − μ_k‖²
```

**步骤 2（移动）**：把每个中心移到分给它的点的均值
```
μ_k = mean{ x⁽ⁱ⁾ : c⁽ⁱ⁾ = k }
```

两步交替，直到分配不再变化。

实现细节：比较距离时用**平方距离**不开方。argmin 结果一样（开方是单调的），省了 m×K 次开方。

### 空簇怎么办

某个中心可能一个点都没分到，均值无定义。两种做法：
- 直接删掉这个簇（K 变成 K−1）
- 随机重新初始化它 ← `mlkit` 用这个，保证返回的中心数永远是 K

## 3. 代价函数（失真 distortion）

```
J(c, μ) = (1/m) Σᵢ ‖x⁽ⁱ⁾ − μ_{c⁽ⁱ⁾}‖²
```

**关键性质：J 单调不增。**

- 步骤 1 让每个点换到更近的中心 → 每一项都不增
- 步骤 2 把中心移到均值，而**均值正是使平方距离和最小的点** → 不增

所以 K-means 必然收敛。**如果你的 J 曾经上升过，那一定是代码有 bug**——这是最好用的自查手段。

（注：实测 `mlkit` 的 J 与 sklearn 的 `inertia_/m` 完全相等：0.7086 vs 0.7086。sklearn 的 inertia_ 不除 m。）

## 4. 随机初始化

**做法**：从训练样本里随机挑 K 个不重复的当初始中心。比在空间里随机撒点好——保证不会有中心落在完全没有数据的区域。

**问题**：K-means 只保证收敛到**局部最优**。坏的初始化会产生肉眼可见的错误聚类（两个中心挤在同一团里，另一团被劈成两半）。

**解法很粗暴但有效**：
```
for i in 1..100:
    随机初始化，跑到收敛
    计算 J
选 J 最小的那次
```
课程建议跑 50~1000 次。`run_kmeans(n_init=10)` 默认 10 次。

## 5. 怎么选 K

### 肘部法（elbow method）

画 J vs K，找曲线"拐弯"的地方。

**课程的态度是保留的**，理由很实在：
1. **J 随 K 单调下降**（中心越多拟合越紧），所以**不能用"J 最小"来选 K**——那永远会选 K = m（每个点自成一簇，J = 0）。
2. 真实数据的曲线常常是一条平滑的弧线，**根本没有明显的肘**。

（本仓库在 3 团数据上跑出 `[16.45, 8.24, 0.71, 0.62, 0.53, 0.48]`，K=3 处的肘非常清楚——但这是合成数据，真实数据很少这么好看。）

### 课程真正推荐的方法

**根据下游用途来选。** T 恤尺码要分 3 档（S/M/L）还是 5 档（XS/S/M/L/XL）？这是一个"多做两个尺码的成本 vs 顾客更合身的收益"的商业权衡，不是失真度能回答的问题。

# 第二部分：异常检测

## 6. 思路

用**正常数据**拟合一个概率密度 p(x)，新样本的 p(x) 低于阈值 ε 就判为异常。

典型应用：飞机发动机质检、服务器监控、金融欺诈（注意：欺诈检测实践中常常是找"异常账户行为"，不是直接抓欺诈本身）。

## 7. 高斯模型

单特征：
```
p(x) = 1/(√(2π)σ) · exp(−(x−μ)²/(2σ²))
```
参数用最大似然估计：`μ = (1/m)Σx⁽ⁱ⁾`，`σ² = (1/m)Σ(x⁽ⁱ⁾−μ)²`

注意分母是 **m 不是 m−1**（这是 ML 估计，也是课程用的；numpy 的 `var()` 默认就是这个）。

多特征——**假设各特征独立，把密度连乘**：
```
p(x) = Π_j p(x_j; μ_j, σ_j²)
```

### 独立性假设

这个假设通常是**错的**，但算法照样能用。不过要清楚它的代价：

**如果两个特征只在"组合"上异常，连乘的边缘密度发现不了。** 比如 CPU 负载高 + 网络流量低 是异常（说明进程死循环了），但单看 CPU 高不异常、单看流量低也不异常。

两种修法：
1. **造组合特征**：`cpu/traffic` 或 `cpu²/traffic`。★课程推荐这个。
2. 用**多元高斯**（带完整协方差矩阵），能自动捕捉相关性。代价是需要 m > n（否则 Σ 奇异），求逆 O(n³)。

`mlkit/anomaly.py` 两种都实现了。

## 8. ε 怎么选：用带标签的交叉验证集

这是异常检测流程里最反直觉的一点：**模型在无标签数据上拟合，但阈值要用有标签的数据来调。**

数据划分（假设 10000 正常 + 20 异常）：
```
训练集   6000 正常，无标签        → 拟合 μ, σ²
CV 集    2000 正常 + 10 异常，有标签 → 选 ε
测试集   2000 正常 + 10 异常，有标签 → 最终评估
```

（异常样本太少时，可以只用 train + cv，不留 test，但那样就没有诚实的最终估计了。）

**评估指标用 F1，绝对不能用准确率**——2% 异常率下"永远不报警"就有 98% 准确率。

```python
det = AnomalyDetector().fit(X_train).tune(X_cv, y_cv)
print(det.epsilon, det.cv_f1_)     # 实测 eps=1.5e-4, F1=0.919, P=1.00, R=0.85
```

## 9. ★ 异常检测 vs 监督学习

同样有一点标签，什么时候用哪个？这是本周最需要理解的判断题。

| | **异常检测** | **监督学习** |
|---|---|---|
| 正样本数量 | 极少（0–20 个） | 较多（几十以上） |
| 负样本 | 很多 | 很多 |
| 异常的形态 | **千奇百怪，未来的异常可能和见过的完全不同** | 未来的正样本与训练里见过的**类似** |
| 逻辑 | 学"正常长什么样"，任何偏离都报警 | 学"正样本长什么样"，找相似的 |
| 例子 | 新型欺诈、飞机发动机新故障模式、黑客攻击 | 垃圾邮件、已知缺陷分类、疾病诊断 |

**判断口诀**：问自己"未来的异常会和我训练集里这几个异常长得像吗？"
- 像 → 监督学习
- 可能完全不像 → 异常检测

垃圾邮件虽然也很不平衡，但垃圾邮件的套路就那么几种，未来的垃圾邮件和过去的很像，所以**用监督学习**。

## 10. 特征工程（异常检测里格外重要）

监督学习能自己学着忽略没用的特征（把 w 压到 0）；**异常检测没有标签可以指导它这么做**，所以特征选得好不好直接决定成败。

### 让特征更像高斯

先画直方图。如果明显偏斜，做变换：
- `log(x)`、`log(x + c)`（c 是小常数，避免 log 0）
- `x^0.5`、`x^0.25`（幂变换）

调 c 或指数直到直方图看起来对称。**训练集做了什么变换，cv/test 集必须做完全一样的变换。**

### 针对漏报做特征工程

流程：找一个 p(x) 很大（被判正常）但实际是异常的样本，**手工看它哪里不对劲**，把那个"不对劲"做成一个新特征。这和 C2W3 的误差分析是同一个思路。

## 11. 代码对照

```python
from mlkit import kmeans as km, anomaly as an, datasets

X, _, _ = datasets.blobs(m=400, k=3, seed=1)
model = km.KMeans(K=3, n_init=20).fit(X)
print(model.inertia_, model.centroids)

Xa, ya = datasets.anomaly_data(400, 20, seed=2)
det = an.AnomalyDetector().fit(Xa[ya == 0][:300]).tune(Xa, ya)
print(det.predict(Xa).sum(), '个被判为异常')
```
