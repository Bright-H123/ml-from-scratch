## 1. 为什么需要 RL

监督学习需要 (x, y) 配对。但"直升机现在应该怎么打杆"、"着陆器现在该点哪个推进器"——**没有人能标出正确答案 y**。

能说清楚的是**奖励 (reward)**：着陆成功 +100，坠毁 −100，燃料消耗 −0.3。然后让算法自己搞明白哪些动作能通向高奖励。

课程的类比：训练狗时你不会逐块肌肉地指导它，你只说"good dog"或"bad dog"。**奖励函数就是这个。**

## 2. 核心概念

```
s     状态 (state)
a     动作 (action)
R(s)  奖励
s'    下一个状态
γ     折扣因子 (discount factor)
π(s)  策略：告诉你在状态 s 该做什么动作
```

一次经历记作 `(s, a, R(s), s')`——这个四元组是所有 RL 算法的基本数据单位。

## 3. 回报与折扣

```
G = R₁ + γR₂ + γ²R₃ + γ³R₄ + …
```

γ 通常取 0.9、0.99、0.999。

**γ 的含义**：
- 数学上：保证无穷和收敛，让算法有唯一解
- 直觉上：**"早拿到的奖励比晚拿到的值钱"** ——和金融里的贴现完全一致，越不耐烦 γ 越小
- 负奖励的效果特别有意思：折扣会让算法**倾向于把坏事往后拖**（今天挨的骂比明年挨的骂更疼），这在实际系统里有时是想要的行为，有时是要小心的副作用

### 火星车例子（本仓库实现了）

6 个状态排成一行，左端奖励 100，右端奖励 40，中间 0。

γ = 0.5 时（很不耐烦）：
```
状态       1        2        3        4
Q(s,左)   100      50       25      12.5
Q(s,右)   25      12.5      20      40
最优动作   左       左       左       右    ← 状态 4 选右，因为近处的 40 折现后更划算
```

γ = 0.9 时（有耐心）：
```
状态       1        2        3        4
Q(s,左)   100      90       81      72.9
Q(s,右)   81      72.9     65.6     40
最优动作   左       左       左       左    ← 全部往左，远处的 100 值得走
```

**同一个环境，只改 γ，最优策略就变了。** 这是理解折扣的最好例子。

## 4. 状态-动作价值函数 Q(s, a)

定义：

> Q(s, a) = 在状态 s 先执行动作 a，**之后一直采取最优行动**，所能获得的回报。

这个定义有点绕（"我要先知道最优策略才能算 Q，可我正是要用 Q 求最优策略"），但它是自洽的，值迭代能算出来。

有了 Q，策略就是免费的：

```
π(s) = argmax_a Q(s, a)
```

最优回报 `V*(s) = max_a Q(s,a)`。

## 5. ★ Bellman 方程

```
Q(s, a) = R(s) + γ · max_{a'} Q(s', a')
          └─┬─┘   └────────┬────────┘
        眼前的奖励      之后最优行动的折现价值
```

读法：**"在 s 做 a 的价值 = 现在马上拿到的奖励 + 折扣 × 从落地的地方开始最优行动的价值"**。

`max_{a'}` 这一项就是定义里"之后一直采取最优行动"的数学表达。正是它让 Q 描述的是"能达到的最好结果"，而不是某个特定策略的结果。

终止状态没有未来，`Q(terminal, a) = R(terminal)`。

**值迭代**：把 Bellman 方程当成赋值语句反复执行，γ<1 时它是一个压缩映射，必然收敛到唯一不动点。

（本仓库 `value_iteration` 求出的解，Bellman 残差 = **0.0**，即精确满足方程。）

## 6. 随机环境

现实里动作不一定如愿（火星车打滑，机器人轮子空转）。这时下一个状态是随机的，Bellman 方程改成取**期望**：

```
Q(s,a) = R(s) + γ · E[ max_{a'} Q(s', a') ]
```

目标从"最大化回报"变成"**最大化期望回报**"。

`MarsRover(misstep_prob=0.25)` 就是这个：有 25% 概率往反方向走。

## 7. 连续状态

真实问题的状态不是 6 个格子，而是连续向量。月球着陆器的状态是 8 维：

```
s = [x, y, ẋ, ẏ, θ, θ̇, l, r]
     位置  速度   角度 角速度  左右腿是否触地(0/1)
```

动作 4 个：什么都不做 / 左推进器 / 主推进器 / 右推进器。

奖励设计（体现了 reward shaping 的思路）：
- 到达停机坪：+100 ~ +140
- 坠毁：−100，安全着陆：+100
- 每条腿触地：+10
- 点主推进器：每帧 −0.3；点侧推进器：每帧 −0.03

**奖励函数的设计往往比算法本身更难**，也更决定最终行为。

## 8. DQN（深度 Q 网络）

状态连续，Q 表存不下，用神经网络逼近 Q。

### 网络结构

```
输入：状态 s（8 维）
隐藏：64 → 64，ReLU
输出：4 个数，分别是 Q(s, a₁) … Q(s, a₄)，linear 激活
```

★ **为什么输出所有动作的 Q，而不是把 (s,a) 一起输入、输出一个数**：这样求 `max_a' Q(s',a')` 只要**一次前向传播**，而不是每个动作跑一次。动作多时差别很大。

### 训练集怎么造

这是 DQN 最巧妙的地方——**把 RL 转成监督学习**：

```
x = s
y = R(s)                                    如果 s' 是终止状态
  = R(s) + γ · max_{a'} Q_target(s', a')    否则
```

然后就是普通的回归训练（MSE 损失）。

★ **只有被执行的那个动作对应的输出该产生梯度**。做法：先前向得到当前的 4 个 Q 值，只把被执行动作那一位替换成 target，其余保持不变——这样其余三位的误差恰好是 0。代码里就是这两行：

```python
y = q_pred.copy()
y[np.arange(len(A)), A] = targets
```

### 目标网络（target network）

y 里用的是 `Q_target` 而不是 `Q` 本身。如果用同一个网络，**每次更新都在移动自己正在追的靶子**，训练会震荡甚至发散。

解法是**软更新**：
```
Q_target ← τ·Q + (1−τ)·Q_target      τ 很小，如 0.001~0.01
```
让靶子慢慢跟随，提供一个稳定的参考。

### 经验回放（replay buffer）

存最近 10,000~100,000 条 `(s, a, r, s', done)`，训练时从里面**随机抽 minibatch**。

解决两个问题：
1. **同一回合内的连续步骤高度相关**，按顺序训练会让更新严重有偏；随机抽样打散相关性
2. **每条经验能被反复使用**，而不是用一次就扔——在"采集经验很贵"的场景（真实机器人）这一点很关键

### ε-贪心探索

```
以 1−ε 概率：a = argmax_a Q(s,a)        利用 (exploit)
以 ε   概率：a = 随机                    探索 (explore)
```

**为什么必须探索**：如果网络初始的随机权重恰好说"主推进器永远是坏主意"，纯贪心的智能体就永远不会点它，也就**永远拿不到反驳这个判断的证据**。ε 强迫它去收集证据。

调度：ε 从 1.0（几乎全随机）逐渐衰减到 0.01 左右。

**课程提醒**：RL 对超参数**比监督学习敏感得多**。同一个问题，超参数差一点可能训练时间差 10 倍甚至完全学不出来。

## 10. RL 的现实处境

Andrew 在总结里说得很坦白：

- RL 在**学术研究**里非常热
- 但在**实际商业应用**里远远少于监督学习/无监督学习
- 在**模拟环境**里效果好，搬到**真实机器人**上往往差很多（sim-to-real gap）
- 学它是因为它是通向未来的一个重要方向，不是因为它现在到处能用

**不要因为学了 RL 就想把手头的问题都套成 RL。** 大多数问题用监督学习更省事。

```python
from mlkit import rl

env = rl.MarsRover(n_states=6, left_reward=100, right_reward=40)

Q2 = rl.q_learning(env, episodes=5000, gamma=0.9)   # 从经验学，不知道转移概率
# 实测：策略与精确解完全一致，Q 值最大差 0.161

agent = rl.DQNAgent(state_dim=6, n_actions=2, hidden=(32,32), gamma=0.9)
# 实测：训练 1500 回合后 Q 值收敛到 [100/81, 90/72.9, 81/65.6, 72.9/40]，
#       与值迭代的解析解完全一致
```
