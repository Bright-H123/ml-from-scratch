# 第一部分：协同过滤

## 1. 问题设定

```
Y (n_items, n_users)   评分矩阵，很多空缺
R (n_items, n_users)   R[i,j] = 1 表示用户 j 评过物品 i
```

目标：填补空缺，给用户推荐他没看过但可能喜欢的物品。

## 2. 如果物品特征 x 已知

那就是每个用户一个独立的线性回归：

```
预测 = w⁽ʲ⁾ · x⁽ⁱ⁾ + b⁽ʲ⁾
J = ½ Σ_{(i,j): r=1} (w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾)² + (λ/2)Σ‖w‖²
```

**注意 `Σ_{(i,j): r=1}`——只对已评分的项求和。** 代码里实现成"误差乘以 R"：没评分的项误差被置零，对代价和梯度贡献都是 0，模型永远不会被要求去解释一个不存在的评分。

## 3. ★ 协同过滤：x 也是要学的参数

现实中我们没有物品特征。协同过滤的做法是**把 x 也当成参数一起学**：

```
J(W, b, X) = ½ Σ_{(i,j): r=1} (w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾ − y⁽ⁱ'ʲ⁾)²
             + (λ/2)Σ_j‖w⁽ʲ⁾‖² + (λ/2)Σ_i‖x⁽ⁱ⁾‖²
```

对三组参数同时做梯度下降：

```
w⁽ʲ⁾ := w⁽ʲ⁾ − α ∂J/∂w⁽ʲ⁾
b⁽ʲ⁾ := b⁽ʲ⁾ − α ∂J/∂b⁽ʲ⁾
x⁽ⁱ⁾ := x⁽ⁱ⁾ − α ∂J/∂x⁽ⁱ⁾    ← 这一行是协同过滤和普通线性回归的全部区别
```

**"协同"的含义**：多个用户对同一部电影的评分共同决定了这部电影的特征向量；而这个特征向量又帮助预测其他用户对它的评分。用户之间在互相帮忙，尽管他们并不认识。

学出来的 x 各维度**没有人类可读的含义**（不是"浪漫程度"、"动作程度"），它就是一组能最好解释评分数据的隐变量。

（本仓库梯度已通过数值检验，误差 3.1e-8；在 60×40 的合成数据上，留出评分的 RMSE = 0.064，而"全部预测平均分"的基线是 0.49，好了 7.7 倍。）

## 4. 二元标签

评分不一定是星级，也可以是 0/1（点了没点、买了没买、看完没看完）。这时把预测改成
```
预测 = g(w⁽ʲ⁾·x⁽ⁱ⁾ + b⁽ʲ⁾)      g = sigmoid
```
损失换成交叉熵，其余完全一样。**这是从线性回归到逻辑回归的同一个改动，套在协同过滤上。**

★ 数据处理上有个坑：`y=0` 要区分"看了没点"和"根本没展示过"。只有前者是真的负样本，后者应该是 R=0（缺失），不是 y=0。

## 5. 均值归一化

**问题**：一个刚注册、什么都没评过的用户，他的代价函数里所有平方误差项都是 0（因为 R 全是 0），只剩正则项 `(λ/2)‖w‖²`。梯度下降会把 w 压到 0，于是模型预测他对所有电影都给 **0 星**。这显然不合理。

**解法**：训练前把每一行（每部电影）减去它的平均评分，预测时再加回去。

```python
Y_norm, Y_mean = normalize_ratings(Y, R)     # 按行减均值，只对已评分项算均值
# 训练用 Y_norm
prediction = X @ W.T + b + Y_mean[:, None]   # 预测加回去
```

这样 w=0 时预测的是**该电影的平均分**，一个合理得多的默认值。顺带还能加快其他用户的收敛。

（实测：给一个零评分的新用户，预测值与各电影均分的相关系数 = 1.000，平均绝对差 = 0.000，完全符合设计。）

**按行（电影）还是按列（用户）归一化？** 课程按行。按列归一化解决的是"某部新电影没人评过"的问题，实践中新用户比新电影更常见。

## 6. 找相似物品

不需要额外模型：

```
相似度 = ‖x⁽ᵏ⁾ − x⁽ⁱ⁾‖²    越小越相似
```

学出来的特征空间里距离近就是相似。这就是网页上"看过这部的人还看了……"的实现。

## 7. 协同过滤的局限

1. **冷启动 (cold start)**
   - 新物品几乎没有评分 → 特征学不准
   - 新用户没评过分 → 只能给平均分
2. **用不上边缘信息**。物品的类型/演员/上映年份、用户的年龄/性别/地区，协同过滤统统看不见——它只看评分矩阵。

这两条正是下面基于内容的过滤要解决的。

# 第二部分：基于内容的过滤

## 8. 双塔结构

| | 协同过滤 | 基于内容 |
|---|---|---|
| 依据 | 和你口味相似的人喜欢什么 | 你的特征和物品的特征匹不匹配 |
| 输入 | 只有评分矩阵 | 用户画像 + 物品描述 |

```
用户特征 x_u ──[用户网络]──> v_u  (维度 32)
物品特征 x_m ──[物品网络]──> v_m  (维度 32)
                              ↓
                    预测 = v_u · v_m
```

★ **两个网络的输入特征维度可以完全不同**（用户可能有 50 维画像，电影有 200 维描述），但**输出维度必须相同**，因为要做点积。

训练：把两个网络看成一个整体，用同一个代价函数

```
J = Σ_{(i,j): r=1} (v_u⁽ʲ⁾·v_m⁽ⁱ⁾ − y⁽ⁱ'ʲ⁾)² + 神经网络正则项
```

反向传播同时更新两个网络。

二元标签时外面套一个 sigmoid：`预测 = g(v_u · v_m)`。

## 9. 大规模部署：检索 + 排序

目录里有一千万部电影，不可能每次请求都全部算一遍。

**① 检索 (Retrieval)** —— 快速生成几百个候选，宁滥勿缺：
- 用户最近看的 10 部电影，各取 10 部最相似的
- 用户最常看的 3 个类型里，各取排名前 10
- 用户所在国家的 Top 20

**关键工程点**：物品向量 v_m 可以**离线预计算**并存起来（物品特征不常变）。所以检索阶段只是一次近邻查找，非常快。

**② 排序 (Ranking)** —— 只对这几百个候选跑完整模型，按 `v_u·v_m` 排序输出。

**候选取多少个**是个可调的权衡：取多了慢，取少了可能漏掉好推荐。做法是离线实验：多取一些候选，看推荐质量有没有明显提升。

## 10. 推荐系统的伦理

课程专门讲了一节，态度很直接：

- 推荐系统的优化目标常常是**参与度/广告收入**，而不是用户福祉
- 阴谋论、极端内容因为参与度高而被放大
- 借贷广告里，高利贷公司因为利润高、能买更贵的广告位而被优先推荐给弱势人群
- **可改进的做法**：不推明确有害的内容；用"是否推广有益内容"作为目标之一；对推荐逻辑保持透明

# 第三部分：PCA

## 11. 做什么

把 n 维特征压缩到 k 维（通常 k=2 或 3），尽量保留数据的方差，然后可以**画出来看**。

## 12. 步骤

1. **每个特征减去均值**（必做）。不去中心的话，第一主成分会被特征的均值方向主导，而不是数据的变化方向。
2. **缩放到可比范围**（通常做）。否则"以米为单位的特征"会仅仅因为单位选择而压过"以公里为单位的特征"。
3. 求新坐标轴：取 X 的前 k 个右奇异向量。

投影和重构：
```
z = U_reduce^T · x          降维
x_approx = U_reduce · z     重构（有损）
```

损失的信息量恰好是 `1 − Σ(解释方差比)`。

**实现用 SVD 而不是对协方差矩阵做特征分解**：数值上更稳，而且根本不用构造协方差矩阵。（实测解释方差比和 sklearn 的 PCA 完全一致：`[0.77834, 0.22087]`。）

## 13. ★ PCA 该用在哪、不该用在哪

| 用途 | 课程态度 |
|---|---|
| **可视化**（降到 2–3 维画图） | ★ 主要用途，推荐 |
| 数据压缩（省存储/传输） | 历史用途，现在存储便宜了，很少用 |
| 加速模型训练 | 历史用途，现代优化器处理宽输入没问题 |
| **防止过拟合** | ❌ **不要这么用**。防过拟合请用正则化 |

最后一条要特别记住。PCA 降维确实会减少参数量、看起来能防过拟合，但它在降维时**完全不看 y**，可能恰好丢掉对预测最有用的那个方向。正则化是知道 y 的，它才是正确的工具。

## 14. 代码对照

```python
from mlkit import recommender as rec, pca, datasets

Y, R, _ = datasets.ratings_matrix(n_users=40, n_items=60, seed=1)
cf = rec.CollaborativeFiltering(n_features=5, lambda_=0.5).fit(Y, R, iterations=800)
print(cf.recommend(user=0, top_n=5, exclude_rated=R))
print(rec.similar_items(cf.X, item=0, top_n=3))

p = pca.PCA(n_components=2).fit(X_highdim)
Z = p.transform(X_highdim)            # 可以直接 scatter(Z[:,0], Z[:,1])
print(p.explained_variance_ratio_)    # 这两维保住了多少信息
```
